## 通用问题

### Q1: 这套课程适合谁？
**A**: 本课程面向以下人群：
- 希望进入 AI 基础设施领域的转行者
- 对 ML 工程基础设施感兴趣的应届毕业生
- 转型至 ML 基础设施岗位的软件工程师
- 拓展至 AI/ML 领域的 DevOps 工程师
- 任何希望系统学习 AI 基础设施的人

前提条件：建议具备基础编程知识和命令行使用经验，但非强制。

---

### Q2: 我需要计算机科学学位吗？
**A**: 不需要！虽然 CS 学位可能有帮助，但并非必需。本课程假设：
- 基础编程经验（最好使用 Python）
- 愿意学习
- 较强的问题解决能力
- 自律的自主学习能力

许多成功的 AI 基础设施工程师是自学成才或来自非 CS 背景。

---

### Q3: 完成本课程足以找到工作吗？
**A**: 本课程为初级岗位提供基础知识。要最大化就业机会：
- 高质量完成所有项目
- 构建额外的个人项目
- 贡献开源项目
- 与专业人士建立联系
- 练习面试问题
- 如有可能，获取实习或自由职业经验

把这当作你的基础——持续学习是职业生涯的一部分。

---

### Q4: 学习仓库和解答仓库有什么区别？
**A**:
- **学习仓库**：包含课程、含存根代码的练习和模板。你在这里完成学习。
- **解答仓库**：包含完整的实现供参考。请在自己完成项目之后再查看。

始终先尝试独立解决问题，再查看解答。

---

### Q5: 我可以使用 AI 助手（ChatGPT、GitHub Copilot 等）吗？
**A**:
- **学习过程中**：有节制地使用。理解 > 完成。
- **调试时**：可以，但要理解解决方案。
- **用于生成整个项目**：不可以。这样你学不到东西。
- **最佳实践**：先独立尝试，然后在特定卡点使用 AI。

目标是获得真实能力，而不仅仅是完成作业。

## 先决条件

### Q6: 我不会 Python。应该先学吗？
**A**: 是的，基础 Python 是必需的。开始本课程之前：
- 完成 Python 基础课程（2-4 周）
- 熟练掌握：变量、函数、循环、类
- 推荐："Python Crash Course" 或 Codecademy Python
- 参加先决条件测验——如果得分 < 70%，请多做 Python 准备

---

### Q7: 开始前需要了解机器学习吗？
**A**: 不需要深入的 ML 知识！你需要：
- **了解** ML 是什么（模型、训练、推理）
- **基本概念**，如特征、预测、准确率
- **能够使用**预训练模型

本课程包含 ML 基础（模块 1）。你将学到足够的知识来部署和管理 ML 系统。

---

### Q8: 我需要 Mac 或 Linux 电脑吗？
**A**: 强烈推荐。虽然 Windows 也能用（尤其是 WSL2）：
- 大多数服务器运行 Linux
- Docker 在 Linux/Mac 上运行更佳
- 行业主要使用 Linux/Mac
- 开发更方便

如果使用 Windows，请安装带 Ubuntu 的 WSL2（适用于 Linux 的 Windows 子系统）。

---

### Q9: 我需要掌握多少数学知识？
**A**: 本课程所需的数学知识很少：
- 基础代数
- 理解百分比和统计知识（有帮助）
- 不需要微积分或高等数学

本课程侧重于基础设施，而非 ML 研究。实现技能比数学证明更重要。

## 技术环境搭建

### Q13: 我的 Docker 安装不工作。帮帮我！
**A**: 常见问题与修复：

**Linux**：
```bash
# 将用户添加到 docker 组
sudo usermod -aG docker $USER
# 注销并重新登录

# 启动 Docker 守护进程
sudo systemctl start docker
sudo systemctl enable docker
```

**Mac/Windows**：
- 确保 Docker Desktop 正在运行
- 检查资源分配（必要时增加）
- 重启 Docker Desktop

**通用**：
- 运行 `docker --version` 验证安装
- 尝试 `docker run hello-world`
- 检查 Docker Desktop 日志
- 详见 `resources/tools.md`

---

### Q14: 我遇到"permission denied"错误。怎么办？
**A**: 通常是 Docker 权限问题：

```bash
# Linux：添加到 docker 组
sudo usermod -aG docker $USER
# 注销并重新登录

# 验证
docker ps
```

对于文件权限问题：
```bash
# 检查所有者
ls -la

# 修复所有权
sudo chown -R $USER:$USER /path/to/directory
```

---

### Q15: 我的电脑很慢。最低配置是什么？
**A**: 最低配置：
- **CPU**：双核（推荐四核）
- **内存**：8GB（推荐 16GB）
- **存储**：50GB 可用空间（推荐 SSD）
- **操作系统**：Ubuntu 20.04+、macOS 10.15+ 或带 WSL2 的 Windows 10

如果电脑吃力：
- 学习时关闭其他应用程序
- 使用轻量级替代方案（单节点 Minikube）
- 考虑云端开发环境（AWS Cloud9、GitHub Codespaces）

---

### Q16: 我可以使用云虚拟机代替本地电脑吗？
**A**: 可以！可选项：
- **AWS EC2**：提供免费套餐
- **Google Cloud**：新用户 $300 额度
- **DigitalOcean**：价格实惠的 Droplet
- **GitHub Codespaces**：云端 VS Code

优点：
- 更好的资源
- 更接近生产环境
- 可随处访问

缺点：
- 依赖网络
- 免费套餐后可能产生费用
- 环境搭建稍复杂

## 学习困难

### Q17: 我在某个概念上卡住了。该怎么办？
**A**: 按照以下步骤：
1. **重新仔细阅读**材料
2. **尝试课程中的示例**
3. **在线搜索**（官方文档、Stack Overflow）
4. **观看相关视频**（YouTube）
5. **在学习小组或社区论坛提问**
6. **休息一下**，以新的视角返回
7. **尝试不同资源**（换个解释方式可能有帮助）

在寻求帮助前，不要卡住超过 1-2 小时。

---

### Q18: 学习进度感觉太快/慢了。怎么办？
**A**:
**太快了**：
- 放慢速度，深度 > 速度
- 补充额外资源
- 多做练习
- 感觉掌握之前不要往下走

**太慢了**：
- 跳到有挑战性的部分
- 尝试提前做项目
- 探索高级变体
- 贡献开源项目以获得真实复杂度

这是自定进度的——根据需要调整！

---

### Q19: 我总忘记学过的内容。如何保持记忆？
**A**: 使用以下技巧：
1. **主动回忆**：定期自我测试
2. **间隔重复**：分别在 1 天、1 周、1 个月后复习
3. **实践项目**：立即应用所学概念
4. **教给别人**：通过讲解来巩固理解
5. **做笔记**：用自己的话写总结
6. **使用闪卡**：用于记忆命令和术语
7. **构建项目**：动手实践是关键

记住：遗忘一些内容是正常的。参考资料的存在自有其价值！

---

### Q20: 我期中考试没通过。现在怎么办？
**A**: 别慌！这是个学习机会：
1. **查看反馈**以找出薄弱环节
2. **重新学习**你遇到困难的模块
3. **在这些领域多做练习**
4. **对难懂的概念尝试其他资源**
5. **在社区渠道寻求帮助**
6. **认真复习后重考**（等待 1 周）

许多成功的学习者第一次也没通过。成长来自于克服困难。

## 项目

### Q21: 我的项目运行不了。什么时候该看解答？
**A**: 仅在以下情况之后才查看解答：
1. **投入了足够时间**尝试（至少 2-3 小时）
2. **系统性地进行了调试**（日志、错误信息、Google 搜索）
3. **在社区中寻求过帮助**
4. **将问题拆解为多个部分**并逐一测试

当你查看解答时：
- 不要直接复制粘贴
- 理解其思路
- 用自己的方式实现
- 记录你学到的东西

---

### Q22: 我可以使用需求中未提及的库吗？
**A**: 可以，但：
- 仍需满足核心需求
- 说明你选择额外库的原因
- 确保它们适合当前任务
- 不要过度设计——简单往往更好

目标是学习基础，而不是构建最花哨的系统。

---

### Q23: 我应该把项目公开放在 GitHub 上吗？
**A**: 是的！好处：
- **作品集**：向雇主展示技能
- **反馈**：社区可以审查并提出建议
- **练习**：养成良好的 Git/GitHub 习惯
- **人脉**：别人可以发现你的工作

只需确保：
- 不包含敏感数据（凭据、API 密钥）
- 有专业的 README
- 提交历史干净整洁
- 定期更新

---

### Q24: 我的项目应该做到多"完美"？
**A**: 目标是：
- **功能完整**：按规格正常运行
- **整洁**：代码组织良好
- **有文档**：有清晰的 README
- **有测试**：具备基本测试

不要追求：
- 生产级的完美
- 包含所有可能的功能
- 零 bug
- 最前沿的优化

目标是"足够好以通过并从中学习"。你以后随时可以改进。

## 工具与环境

### Q32: 我应该使用哪个 IDE？
**A**: 对于本课程：
- **VSCode**（推荐）：免费、轻量、优秀的扩展
- **PyCharm**：Python 表现出色，但较重

### Q33: 我需要记住所有命令吗？
**A**: 不需要！你会通过练习记住常用命令。其他命令：
- 使用速查表（在 `resources/cheat-sheets/` 中提供）
- 查阅官方文档
- 使用命令历史（上箭头、`history` 命令）
- 为常用命令创建别名

理解 > 记忆。知道什么是可行的以及在哪里找到细节。

---

### Q34: 我应该使用 Docker Desktop 还是 Docker Engine？
**A**:
- **Docker Desktop**（Mac/Windows）：设置更简单，包含 GUI
- **Docker Engine**（Linux）：轻量级，仅命令行

学习时：Docker Desktop 没问题。
培养生产思维：学习 Docker Engine 命令。
