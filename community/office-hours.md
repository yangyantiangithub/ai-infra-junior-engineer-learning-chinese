# 虚拟答疑时间

通过虚拟答疑时间获取帮助、提问问题并与其他学习者交流。

---

## 概述

虚拟答疑时间提供：
- **实时帮助**解决课程难题
- **代码审查**针对你的项目
- **职业建议**关于 AI 基础设施岗位
- **社区连接**与同在学习的人
- **动力提升**在你卡住的时候

这些会议旨在以人际互动和指导来补充自学。

---

## 答疑时间如何运作

### 形式
- **虚拟会议**通过 Zoom/Google Meet
- **自由参与**：带着问题来，或者只听
- **屏幕共享**：展示你的代码/错误以寻求帮助
- **协作式**：也能从别人的问题中学习
- **录制**：大多数会议会录制供后续观看（经许可）

### 谁可以参加
- 正在学习课程的任何人员
- 任何技能水平，从初级到高级
- 考虑开始课程的人
- 希望回馈社区的学员

### 可以期待什么
- **轻松氛围**：不做评判，欢迎所有问题
- **以解决问题为核心**：一起解决问题
- **同伴学习**：学习者经常互相帮助
- **实时调试**：现场看解决方案
- **职业讨论**：求职、面试、行业洞察

## 为答疑时间做准备

### 做好准备

为获得最大价值：

1. **准备具体问题**：
   - ✓ "我的 Docker 容器以退出码 137 退出。我已经尝试过 X 和 Y。"
   - ✗ "Docker 不工作。帮帮我？"

2. **提供背景信息**：
   - 你在哪个模块/项目？
   - 你尝试过什么？
   - 错误信息（复制粘贴，不要截图）
   - 相关代码片段

3. **准备好共享屏幕**：
   - 打开你的代码
   - 打开显示错误信息的终端
   - 打开相关标签页的浏览器

4. **准备一个备选问题**：
   - 以防你的主要问题很快得到解答
   - 或者如果其他人的问题占用时间较长

### 携带什么

**技术问题**：
- 代码链接（GitHub 仓库）
- 错误信息（文本，不是截图）
- 预期行为与实际行为的描述
- 你已经尝试过的方法

**项目审查**：
- GitHub 仓库链接
- 你想获得反馈的具体方面
- 已完成自我评估
- 关于改进的问题

**职业问题**：
- 当前简历（可选，用于反馈）
- 目标职位描述
- 具体的职业疑虑

## 会议准则

### 该做的
- ✓ 准时到达或安静地迟到加入
- ✓ 不发言时静音
- ✓ 如果不敢开口，在聊天中提问
- ✓ 如果你知道答案，帮助他人
- ✓ 分享你学到的内容
- ✓ 感谢提供帮助的志愿者
- ✓ 解决问题后反馈结果

### 不该做的
- ✗ 主导整个对话
- ✗ 期望获得私人辅导
- ✗ 分享敏感/专有代码
- ✗ 未经许可录制
- ✗ 对他人的问题粗鲁或不屑一顾
- ✗ 寻求与课程无关的作业或考试帮助
- ✗ 期望别人为你写好解答

### 行为准则
- **尊重**：欢迎所有技能水平
- **包容**：不搞门槛歧视或精英主义
- **协作**：我们一起学习
- **耐心**：解决问题需要时间
- **专业**：使用得体的语言和行为

违反者可能被请出会议。

## 可获得的帮助类型

### 1. 技术调试

**示例**：
- "我的 Docker 容器无法启动"
- "Kubernetes pod 处于 CrashLoopBackOff 状态"
- "CI/CD 流水线在 X 步骤失败"
- "无法从容器连接到数据库"

**流程**：
1. 描述问题
2. 共享屏幕显示错误
3. 一起逐步调试
4. 确定根本原因
5. 实施解决方案

**预计时间**：10-20 分钟

---

### 2. 代码审查

**示例**：
- "我的 Dockerfile 是否优化？"
- "请审查我的 Kubernetes 清单文件"
- "关于我项目结构的反馈"
- "我是否遵循了最佳实践？"

**流程**：
1. 提前共享 GitHub 仓库链接
2. 展示者快速概述（2 分钟）
3. 小组一起审查代码
4. 提供建设性反馈
5. 提出改进建议

**预计时间**：15-25 分钟

---

### 3. 概念性问题

**示例**：
- "我不理解容器网络"
- "HPA 实际上是如何工作的？"
- "ReplicaSet 和 Deployment 有什么区别？"
- "什么时候应该使用 ConfigMap 而不是 Secret？"

**流程**：
1. 提出你的问题
2. 主持人解释概念
3. 小组讨论和举例
4. 问答以澄清

**预计时间**：10-15 分钟

---

### 4. 学习策略

**示例**：
- "我在模块 3 上卡了好几周"
- "如何平衡学习与全职工作？"
- "哪些资源最有帮助？"
- "我应该放慢速度还是跳着学？"

**流程**：
1. 描述你的情况
2. 讨论挑战
3. 集思广益制定策略
4. 制定行动计划

**预计时间**：10-15 分钟

---

### 5. 职业建议

**示例**：
- "雇主真正想要什么技能？"
- "如何谈论自学经历？"
- "我什么时候准备好申请？"
- "简历/作品集反馈"

**流程**：
1. 分享你的职业情况
2. 讨论具体问题
3. 从他人经验中获取建议
4. 制定行动步骤

**预计时间**：10-20 分钟

## 虚拟答疑时间礼仪

### 参会者须知

**音频**：
- 不发言时静音
- 开麦提问或参与讨论
- 使用耳机避免回声
- 找一个安静的地方

**视频**：
- 可开可不开，但鼓励开启
- 可使用虚化背景
- 建议仪表得体

**聊天**：
- 随时在聊天中提问
- 分享有用的链接
- 不要刷屏或聊无关话题
- 保持尊重

**参与**：
- 等待轮到发言
- 不要打断（使用"举手"功能）
- 问题尽量简洁
- 也要给别人发言时间

## FAQ

### Q: 我需要提前报名吗？
**A**: 建议但不强制。报名有助于我们准备和安排问题优先级。如有时间，也欢迎临时加入。

### Q: 如果我的问题没被解答怎么办？
**A**:
- 在 Discord/Slack 中发布，带上 #office-hours 标签
- 报名参加下一次会议（回头客优先）
- 在空闲时段安排一对一（如有）

### Q: 我可以每周参加多次会议吗？
**A**: 可以！只要能帮到你，参加多少次都行。但如果人很多，注意不要占用过多时间。

### Q: 会议会录制吗？
**A**: 大多数会议会录制（经许可）并与参会者分享。如果你不习惯被录制，请告知我们，我们会暂停录制或关闭你的摄像头/音频。

### Q: 我太紧张不敢说话怎么办？
**A**:
- 在聊天中提问
- 只听不说话，从他人那里学习
- 私信主持人
- 从较轻松的会议开始（如职业建议，不那么技术性）

### Q: 我可以带朋友/同事来吗？
**A**: 可以，如果他们也在学习 AI 基础设施的话。未经许可，不允许招聘人员或观察者参加。

### Q: 有面向初学者的专门会议吗？
**A**: 所有会议都欢迎初学者。"没有愚蠢的问题"原则适用。我们曾经都是初学者！

### Q: 如果会议时间不合适怎么办？
**A**:
- 观看录制回放
- 在反馈中申请其他时间
- 在你的时区组建学习小组
- 使用异步支持（Discord、GitHub Discussions）
