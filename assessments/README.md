# 评估概览

## 目的

本课程中的评估有多重目的：
- **自我评估**：衡量你的理解程度并发现知识盲区
- **进度追踪**：衡量在课程中的学习进展
- **就业准备**：根据行业期望验证技能
- **作品集构建**：生成展示能力的成果

## 评估类型

### 1. 先决条件测验
**文件**：`quizzes/prerequisites-quiz.md`

- **何时进行**：开始课程之前
- **时长**：30 分钟
- **题数**：20 道选择题和简答题
- **及格分数**：70%
- **目的**：验证 Python、Linux 和基础 CS 概念方面的基础知识

**涵盖主题**：
- Python 基础
- Linux 命令行
- 基础网络
- 版本控制 (Git)
- 数据库基础

### 2. 模块测验
**位置**：每个课程模块内

- **何时进行**：完成每个模块后
- **时长**：每次 15-20 分钟
- **题数**：每次 10-15 道
- **及格分数**：75%
- **目的**：巩固学习成果，发现需要复习的领域

### 3. 项目评分标准
**文件**：`rubrics/project-rubrics.md`

- **适用范围**：全部 5 个动手项目
- **评分维度**：
  - 功能性 (40%)
  - 代码质量 (25%)
  - 文档 (20%)
  - 最佳实践 (15%)
- **目的**：提供明确的期望和自我评估标准

### 4. 实践考试

#### 期中实践考试
**文件**：`practical-exams/midterm-practical.md`

- **何时进行**：完成项目 1-2 和模块 1-2 后
- **时长**：3 小时
- **形式**：动手编码和部署任务
- **及格分数**：75%
- **主题**：
  - Docker 容器化
  - 基础模型部署
  - 简单监控搭建
  - 常见问题排查

#### 期末实践考试
**文件**：`practical-exams/final-practical.md`

- **何时进行**：完成所有模块和项目后
- **时长**：4 小时
- **形式**：综合顶点项目
- **及格分数**：80%
- **主题**：
  - 端到端 ML 系统部署
  - 多容器编排
  - 监控与日志记录
  - 文档与演示

## 评估时间表

### 建议时间线（12 周制）

```
第 1 周：  先决条件测验
第 2 周：  模块 1 测验
第 3 周：  项目 1 提交
第 4 周：  模块 2 测验
第 5 周：  项目 2 提交
第 6 周：  期中实践考试
第 7 周：  模块 3 测验
第 8 周：  项目 3 提交
第 9 周：  模块 4 测验
第 10 周： 项目 4-5 提交
第 11 周： 复习与实践
第 12 周： 期末实践考试
```

### 自定进度时间线

对于自定进度的学习者，在自信掌握材料后再进行评估：
1. 完成模块中的所有课程
2. 通过练习进行实践
3. 参加模块测验
4. 如果分数 < 75%，复习薄弱环节并重考
5. 进入下一个模块或项目

## 评分等级

### 百分比转字母等级
- **A (90-100%)**：超出预期，已准备好进入下一阶段
- **B (80-89%)**：符合预期，需小幅改进
- **C (70-79%)**：接近预期，建议复习
- **D (60-69%)**：低于预期，需大幅复习
- **F (<60%)**：未达到最低标准，建议重新开始

### 项目评分标准
每个标准评分 1-5 分：
- **5 - 卓越**：超出行业标准
- **4 - 精通**：达到专业标准
- **3 - 合格**：满足基本要求
- **2 - 发展中**：部分满足要求
- **1 - 不足**：未达到要求

## 自我评估指南

### 评估之前

1. **复习材料**：浏览课程笔记和练习
2. **完成所有练习**：不要跳过动手实践
3. **测试你的项目**：确保一切正常运行
4. **阅读文档**：查阅所涉及工具的官方文档

### 评估期间

1. **仔细阅读**：理解题目要求
2. **管理时间**：根据分值分配时间
3. **展示你的工作**：包含注释和说明
4. **全面测试**：验证你的解决方案按预期工作

### 评估之后

1. **回顾错误**：理解答案错误的原因
2. **填补空白**：重新学习得分较低的主题
3. **多加练习**：必要时做额外练习
4. **寻求帮助**：针对困难概念使用社区资源

## 重考政策

### 测验
- **不限重考次数**
- 两次尝试之间必须等待 **24 小时**
- 重考前复习错误答案
- 追踪进步情况

### 实践考试
- 建议最多 **3 次**尝试
- 两次尝试之间等待 **1 周**
- 将失败的尝试作为学习机会
- 有针对性地复习发现的薄弱环节

### 项目
- **可重新提交直到通过**（75%+）
- 针对上次提交的反馈进行改进
- 记录所做的改进
- 重新提交无时间限制

## 作品集开发

利用评估成果构建专业作品集：

### 包含的内容
1. **已完成的项目**及文档
2. **高分实践考试**的提交成果
3. **测验结果**展示学习进展
4. **学习历程反思**文档

### 如何展示
- 创建包含最佳作品的 GitHub 仓库
- 编写 README 解释每个项目
- 包含截图和演示
- 记录克服的挑战

## 反馈与持续改进

### 自我评估问题
每次评估后，反思以下问题：
- 哪些概念对我来说最容易？
- 哪些主题需要更多练习？
- 我的学习方法效果如何？
- 下次我会采取什么不同的做法？

### 进度追踪
使用 `/progress/` 中的进度追踪模板：
- 整体课程进度
- 模块完成状态
- 项目评估分数
- 技能掌握清单

## 学术诚信

### 期望
- 独立完成评估
- 将项目视为学习练习，而不仅是为分数
- 不要分享测验答案或考试解答
- 引用项目中使用的所有外部资源

### 允许使用的资源
- 官方文档
- 课程材料和课程笔记
- Stack Overflow 及类似 Q&A 网站
- 你自己之前的工作

### 不允许的行为
- 复制其他学习者的解答
- 在评估进行中分享答案
- 使用 AI 工具完成整个项目
- 未经署名抄袭代码
