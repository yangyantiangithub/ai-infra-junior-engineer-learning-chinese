## 概述

本文档规定了生产级 ML 系统的完整需求，该系统将模型服务、编排、ML 流水线和可观测性集成到一个统一、可扩展且安全的平台中。

### 范围

系统必须：
- 通过 RESTful API 提供 ML 预测服务
- 自动训练和部署模型
- 根据需求自动扩缩容
- 维持 99.9% 可用性
- 提供完整的可观测性
- 遵循安全最佳实践

### 不在范围内（针对本项目）

- 多区域部署
- 自定义 ML 模型开发（使用预训练模型）
- 实时流式预测
- 模型可解释性功能
- 移动端 SDK 开发

## 功能性需求

### FR-1：完整系统集成

**优先级：** 关键

#### FR-1.1：API 集成
- **描述：** 将项目 1 的模型服务 API 与 Kubernetes 编排集成
- **要求：**
  - API 在 Kubernetes Pod 中运行
  - 配置健康检查（存活和就绪）
  - 服务网格或负载均衡器分发流量
  - 从 ConfigMap 加载配置
  - 从 Kubernetes Secrets 加载密钥
- **验收标准：**
  - 通过 Kubernetes Service 可访问 API
  - 同时运行多个副本
  - 健康检查通过
  - 配置外部化

#### FR-1.2：ML 流水线集成
- **描述：** 将 ML 训练流水线连接到自动化部署工作流
- **要求：**
  - Airflow DAG 按计划触发模型训练
  - 训练完成的模型注册到 MLflow Model Registry
  - 最佳模型自动部署到预发布环境
  - 生产环境需要手动审批
  - 端到端跟踪模型版本
- **验收标准：**
  - 流水线按计划运行（例如每周）
  - 模型附带元数据注册
  - 预发布部署自动化
  - 生产部署需要审批
  - 版本历史可追溯

#### FR-1.3：监控集成
- **描述：** 集成所有系统组件的监控
- **要求：**
  - Prometheus 从所有服务采集指标
  - Grafana 仪表盘展示统一视图
  - 日志聚合到集中式系统（ELK）
  - 配置关键故障告警
  - 分布式追踪（可选但推荐）
- **验收标准：**
  - 所有服务已接入监控
  - 指标在 Grafana 中可见
  - 日志可搜索
  - 告警在测试故障时触发
  - 端到端请求追踪

#### FR-1.4：统一配置管理
- **描述：** 集中管理所有环境的配置
- **要求：**
  - 环境特定配置（开发、预发布、生产）
  - 代码中无硬编码值
  - 密钥安全管理
  - 配置在 Git 中版本管理
  - 变更可通过 Git 历史追溯
- **验收标准：**
  - 配置的唯一真实来源
  - 保持环境一致性
  - Git 中无密钥
  - 配置变更可追踪

#### FR-1.5：单命令部署工作流
- **描述：** 通过单条命令部署整个堆栈
- **要求：**
  - 使用 Helm chart 或 Kustomize 进行部署
  - 自动处理所有依赖
  - 幂等部署（可安全重试）
  - 管理部署顺序（数据库 → API → 监控）
  - 部署后运行验证测试
- **验收标准：**
  - 单条命令部署完整堆栈
  - 部署始终成功
  - 失败的部署被清理
  - 部署后测试通过

### FR-2：CI/CD 流水线

**优先级：** 关键

#### FR-2.1：持续集成（CI）
- **描述：** 每次提交时自动进行测试和验证
- **要求：**
  - 代码质量检查（代码检查、格式化、类型检查）
  - 安全扫描（静态分析、依赖扫描）
  - 单元测试（>80% 代码覆盖率）
  - 集成测试
  - Docker 镜像构建
  - 镜像漏洞扫描
- **验收标准：**
  - CI 在推送/PR 时自动运行
  - 所有检查必须通过才能合并
  - 生成覆盖率报告
  - 检测并报告漏洞
  - 构建产物使用 commit SHA 标记

#### FR-2.2：持续部署 - 预发布
- **描述：** 自动部署到预发布环境
- **要求：**
  - 在合并到 main/develop 分支时触发
  - 部署到预发布 Kubernetes 集群
  - 部署后运行冒烟测试
  - 运行集成测试
  - 运行负载测试
  - 成功/失败时发送通知
- **验收标准：**
  - 合并后 10 分钟内更新预发布环境
  - 所有测试通过
  - 失败时自动回滚
  - 团队收到部署状态通知

#### FR-2.3：持续部署 - 生产
- **描述：** 需审批的受控生产部署
- **要求：**
  - 手动审批门（团队负责人或经理）
  - 金丝雀部署策略（10% → 100%）
  - 部署期间监控错误率
  - 出错时自动回滚
  - 仅当指标健康时才推进
  - 部署的全面日志记录
- **验收标准：**
  - 生产部署前需要审批
  - 金丝雀部署已测试
  - 自动回滚正常工作
  - 部署期间零停机
  - 部署时间 <10 分钟

#### FR-2.4：自动模型部署
- **描述：** 将模型从注册表部署到服务基础设施
- **要求：**
  - 从 MLflow Model Registry 拉取模型
  - 用新模型版本更新 ConfigMap
  - 重启 Pod 以加载新模型
  - A/B 测试框架用于模型比较
  - 模型回滚能力
- **验收标准：**
  - 新模型自动部署
  - Pod 加载新模型
  - A/B 测试正确分流流量
  - 回滚在 <5 分钟内完成

### FR-3：高可用性与可靠性

**优先级：** 关键

#### FR-3.1：多副本部署
- **描述：** 运行多个副本以实现容错
- **要求：**
  - 生产环境至少 3 个副本
  - 副本分布在多个节点/可用区
  - 反亲和规则防止副本共置
  - 设置资源请求和限制
- **验收标准：**
  - 运行 3 个以上副本
  - 分布在多个节点上
  - 单节点故障不影响服务
  - 执行资源限制

#### FR-3.2：零停机更新
- **描述：** 在不中断服务的情况下部署更新
- **要求：**
  - 滚动更新策略
  - maxSurge: 1, maxUnavailable: 0
  - 健康检查防止过早流量接入
  - 旧 Pod 在终止前排空
- **验收标准：**
  - 更新完成无 5xx 错误
  - 更新期间无请求丢失
  - 流量逐步切换
  - 旧版本平滑排空

#### FR-3.3：自动自愈
- **描述：** 从 Pod 故障中自动恢复
- **要求：**
  - 存活探测重启不健康的 Pod
  - 就绪探测将 Pod 从负载均衡器移除
  - CrashLoopBackoff 检测与告警
  - Pod 自动重启
- **验收标准：**
  - 故障 Pod 在 30 秒内重启
  - 不健康的 Pod 从轮替中移除
  - Pod 故障期间服务持续可用
  - 重复故障时发送告警

#### FR-3.4：负载均衡
- **描述：** 在副本之间均匀分发流量
- **要求：**
  - Kubernetes Service 负载均衡
  - 按需启用会话亲和性
  - Pod 终止时排空连接
  - 请求公平分配
- **验收标准：**
  - 流量均匀分布
  - 无单个 Pod 过载
  - 优雅的连接处理
  - 跟踪负载指标

#### FR-3.5：自动扩缩容
- **描述：** 根据负载自动调整副本数
- **要求：**
  - 配置 Horizontal Pod Autoscaler（HPA）
  - 基于 CPU（70%）和内存（80%）扩缩容
  - 最小副本数：3，最大副本数：20
  - 可选自定义指标（请求数/秒）
  - 配置扩缩容延迟
- **验收标准：**
  - HPA 在负载高时扩容
  - HPA 在空闲时缩容
  - 扩缩容在 2 分钟内完成
  - 无频繁抖动（快速扩缩容）

#### FR-3.6：断路器
- **描述：** 防止依赖项引发级联故障
- **要求：**
  - 数据库连接的断路器
  - MLflow API 调用的断路器
  - 带指数退避的重试逻辑
  - 断路器打开时的降级响应
- **验收标准：**
  - 重复故障时断路器打开
  - 返回降级响应
  - 依赖恢复后断路器关闭
  - 指标跟踪断路器状态

### FR-4：安全实现

**优先级：** 关键

#### FR-4.1：API 认证
- **描述：** 要求所有 API 端点进行认证
- **要求：**
  - API 密钥认证（请求头: X-API-Key）
  - 支持多个 API 密钥（管理员、客户端）
  - 密钥存储在 Kubernetes Secrets 中
  - OAuth 2.0 可选但推荐
  - 每个 API 密钥限流
- **验收标准：**
  - 未认证请求被拒绝（401）
  - 无效 API 密钥被拒绝（403）
  - 不同密钥具有不同权限
  - 每个密钥执行限流

#### FR-4.2：TLS/HTTPS 加密
- **描述：** 加密所有外部通信
- **要求：**
  - cert-manager 用于自动证书管理
  - Let's Encrypt 获取证书
  - 在 Ingress 终止 TLS
  - HTTP → HTTPS 重定向
  - 证书自动续期
- **验收标准：**
  - 所有外部流量使用 HTTPS
  - 证书有效且受信任
  - HTTP 重定向到 HTTPS
  - 自动续期正常工作（使用预发布证书测试）

#### FR-4.3：密钥管理
- **描述：** 安全管理敏感凭据
- **要求：**
  - 使用 Kubernetes Secrets 存储敏感数据
  - Git 仓库中无密钥
  - 推荐使用 Sealed Secrets 或 Vault
  - 密钥以环境变量形式注入
  - 最小权限原则
- **验收标准：**
  - 代码或 Git 中无密钥
  - 密钥静态加密
  - Pod 仅访问所需密钥
  - 记录密钥轮换流程

#### FR-4.4：网络策略
- **描述：** 限制 Pod 间通信
- **要求：**
  - 每个服务配置 NetworkPolicy
  - 默认拒绝入站/出站
  - 显式允许必要通信
  - 命名空间隔离
  - DNS 始终允许
- **验收标准：**
  - 策略已执行（使用 kubectl 测试）
  - 未授权通信被阻止
  - 必要通信被允许
  - 策略已记录

#### FR-4.5：RBAC（基于角色的访问控制）
- **描述：** 控制对 Kubernetes 资源的访问
- **要求：**
  - 每个应用使用 ServiceAccount
  - 角色具有最小权限
  - RoleBinding 进行关联
  - 不使用默认 ServiceAccount
  - 启用审计日志
- **验收标准：**
  - 每个 Pod 使用自定义 ServiceAccount
  - Pod 无法访问未授权资源
  - RBAC 经过测试和验证
  - 权限已记录

#### FR-4.6：输入验证
- **描述：** 验证并清理所有输入
- **要求：**
  - 文件类型验证（仅限图片）
  - 文件大小限制（最大 10MB）
  - MIME 类型检查
  - SQL 注入防护
  - XSS 防护
- **验收标准：**
  - 无效文件被拒绝
  - 超大文件被拒绝
  - 恶意输入被清理
  - 错误消息不泄露信息

#### FR-4.7：限流
- **描述：** 防止滥用和 DoS 攻击
- **要求：**
  - 全局限流：100 请求/分钟
  - 端点特定限制（/predict: 10 请求/分钟）
  - 按 IP 和 API 密钥限流
  - 超过限制时返回 429 响应
  - 响应中包含限流头
- **验收标准：**
  - 限制已执行
  - 过多请求被阻止
  - 合法流量不受影响
  - 指标跟踪限流情况

### FR-5：自动化 ML 生命周期

**优先级：** 高

#### FR-5.1：定时模型重新训练
- **描述：** 按计划自动重新训练模型
- **要求：**
  - Airflow DAG 每周执行一次
  - 数据漂移检测触发重新训练
  - 也支持手动触发
  - 训练流水线端到端运行
  - 结果记录到 MLflow
- **验收标准：**
  - 训练按计划运行
  - 漂移检测正常工作
  - 手动触发正常工作
  - 所有运行都已记录

#### FR-5.2：自动模型评估
- **描述：** 评估并注册训练好的模型
- **要求：**
  - 在预留测试集上评估模型
  - 指标：准确率、精确率、召回率、F1
  - 与生产模型进行比较
  - 仅在性能提升时注册
  - 跟踪元数据（数据集版本、超参数）
- **验收标准：**
  - 评估自动化
  - 仅注册优秀模型
  - 元数据完整
  - 显示对比指标

#### FR-5.3：自动预发布部署
- **描述：** 将获批模型部署到预发布环境
- **要求：**
  - 模型在 MLflow 中标记为"Staging"
  - 自动部署到预发布环境
  - 部署后运行冒烟测试
  - 集成测试验证功能
- **验收标准：**
  - 预发布部署自动化
  - 推进前测试通过
  - 失败的部署已回滚
  - 团队收到状态通知

#### FR-5.4：A/B 测试框架
- **描述：** 在生产环境中比较模型版本
- **要求：**
  - 在模型版本之间分流流量
  - 按版本跟踪指标
  - 统计显著性测试
  - 手动推进优胜版本
- **验收标准：**
  - 流量正确分流（例如 90/10）
  - 指标按版本分离
  - 实现统计检验
  - 推进工作流清晰

#### FR-5.5：模型版本控制与回滚
- **描述：** 跟踪和回滚模型版本
- **要求：**
  - 所有模型在 MLflow 中版本管理
  - ConfigMap 跟踪当前版本
  - 回滚脚本更改版本
  - Pod 自动重新加载
- **验收标准：**
  - 版本历史完整
  - 回滚在 <5 分钟内完成
  - Pod 加载回滚后的版本
  - 回滚期间无数据丢失

#### FR-5.6：数据流水线自动化
- **描述：** 自动化数据摄入与处理
- **要求：**
  - 每日从数据源摄入数据
  - 数据验证检查
  - 使用 DVC 进行数据版本控制
  - 特征工程自动化
  - 流水线失败时告警团队
- **验收标准：**
  - 数据流水线每日运行
  - 验证捕获问题
  - 数据已版本化
  - 团队在失败时收到告警

### FR-6：完整可观测性

**优先级：** 高

#### FR-6.1：指标收集
- **描述：** 从所有组件收集指标
- **要求：**
  - Prometheus 采集所有服务
  - 应用指标（请求率、延迟、错误）
  - 基础设施指标（CPU、内存、磁盘）
  - ML 指标（预测延迟、模型准确率）
  - 业务逻辑的自定义指标
- **验收标准：**
  - 所有服务已接入
  - 指标在 Prometheus 中可用
  - 保留期：30 天
  - 查询性能可接受

#### FR-6.2：集中式日志
- **描述：** 将日志聚合到可搜索的系统
- **要求：**
  - ELK 栈（Elasticsearch、Logstash、Kibana）
  - 收集所有 Pod 日志
  - 结构化日志（JSON 格式）
  - 日志级别：DEBUG、INFO、WARN、ERROR
  - 搜索和过滤功能
- **验收标准：**
  - 所有 Pod 的日志已聚合
  - 搜索功能覆盖所有日志
  - 保留期：30 天
  - 性能可接受

#### FR-6.3：分布式追踪（可选）
- **描述：** 跨服务追踪请求
- **要求：**
  - Jaeger 或 Zipkin 集成
  - Trace ID 传播
  - 日志中的 Trace 上下文
  - 性能影响 <5%
- **验收标准：**
  - 端到端追踪可见
  - 延迟分解显示
  - 错误追踪已捕获
  - 开销可接受

#### FR-6.4：告警
- **描述：** 对关键故障进行告警
- **要求：**
  - Alertmanager 用于路由
  - 告警类型：宕机、高错误率、高延迟、磁盘空间
  - 多种通知渠道（Slack、邮件、PagerDuty）
  - 告警严重级别
  - 告警静默和确认
- **验收标准：**
  - 告警在测试故障时触发
  - 通知已接收
  - 无误报
  - 告警文档完整

#### FR-6.5：仪表盘
- **描述：** 为利益相关者可视化系统健康状态
- **要求：**
  - 每个组件的 Grafana 仪表盘
  - 执行摘要仪表盘
  - SLO/SLI 仪表盘
  - ML 流水线仪表盘
  - 实时更新
- **验收标准：**
  - 创建 4 个以上仪表盘
  - 可视化清晰
  - 启用自动刷新
  - 与团队共享

#### FR-6.6：SLO/SLI 跟踪
- **描述：** 跟踪服务等级目标与指标
- **要求：**
  - SLO：99.9% 可用性
  - SLI：可用性、延迟（P95、P99）、错误率
  - 错误预算计算
  - 月度 SLO 报告
- **验收标准：**
  - SLI 持续测量

## 安全需求

### 数据安全

1. **传输加密**
   - 所有外部流量：TLS 1.2+
   - 内部流量：mTLS（可选但推荐）

2. **静态加密**
   - 数据库：加密卷
   - 对象存储：服务端加密
   - Kubernetes Secrets：在 etcd 中加密

3. **数据隐私**
   - 不记录 PII
   - 执行数据保留策略
   - GDPR 合规（如适用）

### 应用安全

1. **输入验证**
   - 文件类型白名单
   - 文件大小限制
   - SQL 注入防护
   - XSS 防护

2. **输出编码**
   - JSON 响应正确编码
   - 错误消息不泄露敏感信息

3. **认证与授权**
   - API 密钥认证
   - Kubernetes RBAC
   - 最小权限原则

### 基础设施安全

1. **网络安全**
   - 执行 NetworkPolicy
   - Ingress 防火墙规则
   - 无不必要的暴露端口

2. **容器安全**
   - 容器中使用非 root 用户
   - 只读根文件系统
   - 无特权容器
   - CI 中的镜像扫描

3. **密钥管理**
   - Kubernetes Secrets（最低要求）
   - HashiCorp Vault（推荐）
   - Git 中无密钥
   - 记录密钥轮换流程

### 合规性

1. **审计日志**
   - 记录所有 API 调用
   - 记录认证尝试
   - 记录配置变更
   - 日志防篡改（不可变存储）

2. **漏洞管理**
   - 每周依赖扫描
   - 每月安全审查
   - CVE 监控
   - 补丁管理流程
