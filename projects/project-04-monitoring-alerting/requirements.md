## 功能需求

### FR-1：指标采集与存储

#### FR-1.1：部署 Prometheus 用于指标采集

**描述**：将 Prometheus 设置为中央指标采集和存储系统。

**要求**：
- 使用 Docker Compose 部署 Prometheus 2.47+
- 配置持久化存储，保留 30 天
- 设置服务发现以自动检测目标
- 启用远程写入以实现长期存储（可选）
- 配置多个 Prometheus 实例的高可用（高级）

**验收标准**：
- [ ] Prometheus 正在运行且可通过 `http://localhost:9090` 访问
- [ ] 指标按 30 天保留策略存储
- [ ] 时间序列中无数据缺口
- [ ] 常见查询的性能 < 1 秒
- [ ] 存储使用量在预期范围内

#### FR-1.2：配置服务发现

**描述**：无需手动配置即可自动发现监控目标。

**要求**：
- Kubernetes 服务发现（如果使用 K8s）
- 基于文件的服务发现（用于静态目标）
- 基于 DNS 的服务发现
- 自动重新标记已发现的目标

**验收标准**：
- [ ] 新服务在 1 分钟内自动被发现
- [ ] 服务下线时被移除
- [ ] 所有目标应用了正确的标签
- [ ] 没有孤立的采集配置

#### FR-1.3：采集基础设施指标

**描述**：监控所有基础设施组件的系统级指标。

**采集的指标**：
- **CPU**：每核心使用率、平均负载、窃取时间
- **内存**：总量、已用、可用、交换空间使用率
- **磁盘**：每个挂载点使用率、I/O 操作、吞吐量
- **网络**：发送/接收字节数、数据包错误、TCP 连接数

**验收标准**：
- [ ] Node Exporter 部署在所有节点上
- [ ] Prometheus 中所有系统指标可用
- [ ] 每 15 秒采集一次指标
- [ ] 无缺失数据点

#### FR-1.4：采集应用指标

**描述**：跟踪应用级别的性能和行为指标。

**采集的指标**：
- **HTTP 请求**：按方法、端点、状态码统计的总请求数
- **请求时长**：带分位数的直方图（P50、P95、P99）
- **错误率**：每个端点的 4xx 和 5xx 错误
- **活跃连接数**：当前活跃连接数
- **请求大小**：请求/响应大小的直方图

**验收标准**：
- [ ] 应用使用 `prometheus_client` 库进行了仪表化
- [ ] 所有服务暴露 `/metrics` 端点
- [ ] 所有 HTTP 请求被跟踪
- [ ] 延迟桶配置适当

#### FR-1.5：采集 ML 指标

**描述**：监控 ML 特定的模型性能和健康指标。

**采集的指标**：
- **每秒预测数**：按模型的预测速率
- **推理延迟**：P50、P95、P99 推理时长
- **模型准确率**：当前模型准确率（每日更新）
- **预测置信度**：置信度分数的分布
- **数据漂移**：每个特征的漂移分数
- **缺失特征**：缺失特征的请求数

**验收标准**：
- [ ] 预测代码中已仪表化所有 ML 指标
- [ ] 指标实时更新
- [ ] 历史趋势可见
- [ ] 漂移检测已集成

### FR-4：告警与通知

**要求**：

- [ ] 告警正确分组
- [ ] 去重正常工作

#### FR-4.2：基础设施告警规则

**描述**：定义基础设施问题的告警。

**必需的告警**：

1. **CPU 使用率过高**
   - **条件**：CPU > 80% 持续 5 分钟
   - **严重级别**：警告
   - **操作**：检查负载，考虑扩容

2. **内存使用率过高**
   - **条件**：内存 > 85% 持续 5 分钟
   - **严重级别**：警告
   - **操作**：检查内存泄漏，重启服务

3. **磁盘空间不足**
   - **条件**：磁盘可用空间 < 15%
   - **严重级别**：严重
   - **操作**：清理日志，扩展存储

4. **服务宕机**
   - **条件**：目标 2 分钟不可达
   - **严重级别**：严重
   - **操作**：重启服务，检查日志

**验收标准**：
- [ ] Prometheus 中已配置所有告警规则
- [ ] 超出阈值时告警触发
- [ ] 告警注释包含手册链接
- [ ] 严重级别设置正确

#### FR-4.3：应用告警规则

**描述**：监控应用健康与性能。

**必需的告警**：

1. **错误率过高**
   - **条件**：5xx 错误 > 5% 持续 5 分钟
   - **严重级别**：严重
   - **操作**：检查日志，必要时回滚

2. **延迟过高**
   - **条件**：P95 延迟 > 1 秒持续 5 分钟
   - **严重级别**：警告
   - **操作**：分析应用，优化查询

3. **吞吐量过低**
   - **条件**：请求速率 < 1 req/s 持续 10 分钟
   - **严重级别**：信息
   - **操作**：检查是否预期，调查流量下降原因

4. **响应时间过长**
   - **条件**：P99 延迟 > 5 秒
   - **严重级别**：警告
   - **操作**：识别慢端点，优化

**验收标准**：
- [ ] 应用告警已配置
- [ ] 阈值已根据实际工作负载调整
- [ ] 测试中无误报
- [ ] 告警描述清晰

#### FR-4.4：ML 模型告警规则

**描述**：及早检测 ML 特定问题。

**必需的告警**：

1. **模型准确率下降**
   - **条件**：准确率 < 85% 持续 10 分钟
   - **严重级别**：严重
   - **操作**：检查数据质量，考虑重新训练

2. **检测到数据漂移**
   - **条件**：漂移分数 > 0.5 持续 5 分钟
   - **严重级别**：警告
   - **操作**：分析分布偏移，重新训练模型

3. **推理延迟过高**
   - **条件**：P99 推理 > 500ms 持续 5 分钟
   - **严重级别**：警告
   - **操作**：优化模型，检查 GPU 利用率

4. **预测置信度过低**
   - **条件**：平均置信度 < 70% 持续 10 分钟
   - **严重级别**：警告
   - **操作**：调查输入数据，检查模型版本

**验收标准**：
- [ ] ML 告警正确触发
- [ ] 漂移检测已集成
- [ ] 性能阈值适当
- [ ] 手册流程已文档化

## 服务级别指标（SLI）

### 应用 SLI

| SLI | 定义 | 目标 | 测量方式 |
|-----|------------|--------|-------------|
| **可用性** | 成功请求的百分比 | 99.9% | `(2xx+3xx 请求) / 总请求数` |
| **延迟** | P95 响应时间 | < 200ms | `histogram_quantile(0.95, http_request_duration_seconds)` |
| **错误率** | 失败请求的百分比 | < 1% | `5xx 请求 / 总请求数 * 100` |
| **吞吐量** | 每秒请求数 | > 100 | `rate(http_requests_total[5m])` |

### ML 模型 SLI

| SLI | 定义 | 目标 | 测量方式 |
|-----|------------|--------|-------------|
| **准确率** | 模型预测准确率 | > 90% | `正确预测数 / 总预测数` |
| **推理延迟** | P95 推理时间 | < 100ms | `histogram_quantile(0.95, model_inference_duration_seconds)` |
| **预测吞吐量** | 每秒预测数 | > 50 | `rate(model_predictions_total[5m])` |
| **漂移分数** | 数据分布漂移 | < 0.5 | `data_drift_score`（PSI 或 KS 统计量） |

### 基础设施 SLI

| SLI | 定义 | 目标 | 测量方式 |
|-----|------------|--------|-------------|
| **CPU 利用率** | 平均 CPU 使用率 | < 70% | `100 - avg(rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100` |
| **内存利用率** | 平均内存使用率 | < 80% | `(1 - node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes) * 100` |
| **磁盘利用率** | 磁盘使用率 | < 85% | `(node_filesystem_size_bytes - node_filesystem_avail_bytes) / node_filesystem_size_bytes * 100` |

## 服务级别目标（SLO）

### 可用性 SLO

**目标**：99.9% 可用性（月度）

**允许的**：
- 每月 43.2 分钟停机时间
- 每年 8.64 小时停机时间

**测量窗口**：30 天滚动

**告警阈值**：7 天内可用性 < 99.95%（提前预警）

### 延迟 SLO

**目标**：95% 的请求在 < 200ms 内完成

**测量方式**：5 分钟窗口内的 P95 延迟

**告警阈值**：P95 > 250ms 持续 10 分钟

### 错误率 SLO

**目标**：错误率 < 1%

**测量方式**：5 分钟内 5xx 错误 / 总请求数

**告警阈值**：错误率 > 2% 持续 5 分钟

### 模型准确率 SLO

**目标**：准确率 > 90%（每日）

**测量方式**：基于真实标签计算的准确率

**告警阈值**：准确率 < 85% 持续 1 小时
