## 功能需求

### FR-1：模型加载与推理

#### FR-1.1：模型选择与加载
**描述：** 应用必须在启动时加载一个预训练的图像分类模型。

**支持的模型：**
- ResNet-50（推荐给初学者）
- MobileNetV2（替代方案，更轻量的模型）

**需求：**
- 模型必须在应用初始化期间加载
- 如果模型权重不存在，应自动下载
- 加载错误必须被捕获并记录日志
- 模型必须设置为评估模式（非训练模式）

**验收标准：**
- [ ] 启动时模型在 30 秒内成功加载
- [ ] 如果模型加载失败，应用以清晰错误信息优雅退出
- [ ] 模型被缓存，不在每次请求时重新加载
- [ ] 加载进度以 INFO 级别记录日志

#### FR-1.2：图片上传处理
**描述：** 通过 HTTP POST 请求接受图片上传。

**需求：**
- 支持 multipart/form-data 文件上传
- 接受常见图片格式：JPEG、PNG、BMP、GIF
- 验证文件确实是图片（不只检查扩展名）
- 强制执行最大文件大小限制（10MB）

**验收标准：**
- [ ] 端点接受带有 'file' 字段的 multipart/form-data
- [ ] 拒绝非图片文件，返回 HTTP 400
- [ ] 拒绝大于 10MB 的文件，返回 HTTP 413
- [ ] 优雅地处理损坏的图片，返回 HTTP 400

#### FR-1.3：图片预处理
**描述：** 根据模型要求预处理上传的图片。

**需求：**
- 将图片转换为 RGB 格式（处理灰度图和 RGBA）
- 将图片调整为 224x224 像素
- 应用 ImageNet 归一化（mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225]）
- 转换为与 ML 框架兼容的 tensor 格式

**验收标准：**
- [ ] 所有图片成功转换为 RGB
- [ ] 图片保持宽高比调整大小（中心裁剪）
- [ ] 归一化正确应用
- [ ] 典型图片预处理在 50ms 内完成

#### FR-1.4：预测生成
**描述：** 生成 top-K 预测结果，包含类别名称和置信度分数。

**需求：**
- 默认返回前 5 个预测结果
- 每个预测结果包含类别名称/标签
- 每个预测结果包含置信度分数（概率）
- 应用 softmax 将 logits 转换为概率
- 将类别索引映射为人类可读的标签（ImageNet 类别）

**验收标准：**
- [ ] 返回正好 5 个预测结果（除非指定了 top_k 参数）
- [ ] 预测结果按置信度排序（最高在前）
- [ ] 置信度分数之和约为 1.0（误差在 0.01 以内）
- [ ] 类别标签是人类可读的（例如 "golden retriever"，而不是 "n02099601"）

#### FR-1.5：模型操作的错误处理
**描述：** 优雅地处理模型相关的错误。

**需求：**
- 在推理过程中捕获内存不足错误
- 处理模型文件损坏或权重缺失
- 检测不兼容的输入形状
- 处理框架特定错误（PyTorch/TensorFlow）

**验收标准：**
- [ ] OOM 错误返回 HTTP 503 并带有 retry-after 头部
- [ ] 缺失的模型权重触发自动下载或优雅失败
- [ ] 无效的输入形状返回 HTTP 400 并带有描述性消息
- [ ] 所有模型错误以 ERROR 级别记录，包含堆栈跟踪

### FR-2：REST API 实现

#### FR-2.1：/predict 端点
**描述：** 单张图片推理的主要端点。

**规范：**
```
POST /predict
Content-Type: multipart/form-data

请求体：
- file: 图片文件（必填）
- top_k: 返回的预测数量（可选，默认=5）

响应（200 OK）：
{
  "success": true,
  "predictions": [
    {
      "class": "golden_retriever",
      "confidence": 0.89,
      "rank": 1
    },
    ...
  ],
  "latency_ms": 234,
  "timestamp": "2025-10-18T10:30:45Z"
}

错误响应（4xx/5xx）：
{
  "success": false,
  "error": {
    "code": "INVALID_IMAGE_FORMAT",
    "message": "Uploaded file is not a valid image",
    "correlation_id": "req-12345678"
  }
}
```

**验收标准：**
- [ ] 端点可通过 POST /predict 访问
- [ ] 接受 multipart/form-data 请求
- [ ] 返回 JSON 响应
- [ ] 包含延迟测量
- [ ] 每次请求都记录关联 ID

#### FR-2.2：/health 端点
**描述：** 用于监控和负载均衡的健康检查端点。

**规范：**
```
GET /health

响应（200 OK）：
{
  "status": "healthy",
  "model_loaded": true,
  "model_name": "resnet50",
  "uptime_seconds": 3600,
  "timestamp": "2025-10-18T10:30:45Z"
}

响应（503 服务不可用）：
{
  "status": "unhealthy",
  "model_loaded": false,
  "reason": "Model failed to load",
  "timestamp": "2025-10-18T10:30:45Z"
}
```

**验收标准：**
- [ ] 响应时间 < 100ms
- [ ] 应用健康时返回 200
- [ ] 模型未加载或发生严重错误时返回 503
- [ ] 无需认证
- [ ] 可频繁调用（监控用途）

#### FR-2.3：/info 端点
**描述：** 提供模型和 API 元数据。

**规范：**
```
GET /info

响应（200 OK）：
{
  "model": {
    "name": "resnet50",
    "framework": "pytorch",
    "version": "2.0.0",
    "input_shape": [224, 224, 3],
    "output_classes": 1000
  },
  "api": {
    "version": "1.0.0",
    "endpoints": ["/predict", "/health", "/info"]
  },
  "limits": {
    "max_file_size_mb": 10,
    "max_image_dimension": 4096,
    "timeout_seconds": 30
  }
}
```

**验收标准：**
- [ ] 返回完整的元数据
- [ ] 信息准确且最新
- [ ] 无需认证
- [ ] 对 API 发现有用

#### FR-2.4：请求验证
**描述：** 在处理之前验证所有传入请求。

**需求：**
- 检查 /predict 的 Content-Type 头部
- 验证 multipart 表单中存在 file 字段
- 确认文件不为空
- 在读取到内存之前检查文件大小
- 如果提供了 top_k 参数则进行验证（1-10 范围）

**验收标准：**
- [ ] 缺少 file 字段返回 HTTP 400
- [ ] 空文件返回 HTTP 400
- [ ] 无效的 Content-Type 返回 HTTP 415
- [ ] 无效的 top_k 返回 HTTP 400 并附带说明

#### FR-2.5：响应格式
**描述：** 所有端点使用一致的 JSON 响应格式。

**需求：**
- 使用 JSON 作为默认 Content-Type
- 包含成功/错误指示器
- 所有响应中包含时间戳
- 字段名使用 snake_case
- 开发环境美化输出，生产环境压缩输出

**验收标准：**
- [ ] 所有响应都是有效的 JSON
- [ ] Content-Type 头部设置为 application/json
- [ ] 一致的字段命名约定
- [ ] 时间戳使用 ISO 8601 格式

### FR-3：错误处理

#### FR-3.1：结构化错误响应
**描述：** 返回结构化、信息丰富的错误响应。

**错误响应格式：**
```json
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "Human-readable error message",
    "correlation_id": "req-xxxxxxxx",
    "timestamp": "2025-10-18T10:30:45Z",
    "details": {}  // 可选的额外上下文
  }
}
```

**错误码：**
- `INVALID_IMAGE_FORMAT` - 文件不是有效的图片
- `FILE_TOO_LARGE` - 文件超出大小限制
- `MISSING_FILE` - 请求中没有文件
- `MODEL_ERROR` - 模型推理失败
- `OUT_OF_MEMORY` - 操作内存不足
- `TIMEOUT` - 请求处理超时
- `INTERNAL_ERROR` - 意外的服务器错误

**验收标准：**
- [ ] 所有错误都使用此格式
- [ ] 错误码一致且已记录
- [ ] 消息清晰且可操作
- [ ] 关联 ID 支持请求跟踪

#### FR-3.2：内存不足处理
**描述：** 优雅地处理 OOM 情况。

**需求：**
- 在模型加载期间捕获内存错误
- 在推理期间捕获内存错误
- 返回 HTTP 503 并带有 Retry-After 头部
- 记录 OOM 事件用于容量规划
- 尝试恢复（清除缓存等）

**验收标准：**
- [ ] 推理期间的 OOM 不会导致应用崩溃
- [ ] 返回 HTTP 503 并带有适当的消息
- [ ] Retry-After 头部建议合理的延迟（60 秒）
- [ ] 恢复后应用继续服务请求

#### FR-3.3：无效输入处理
**描述：** 处理所有形式的无效输入。

**无效输入类型：**
- 损坏的图片文件
- 非图片文件（PDF、文本文件等）
- 不支持的格式的图片
- 超大图片（> 10000x10000）
- 空文件
- 错误的 Content-Type

**验收标准：**
- [ ] 每种无效输入类型都有特定的错误码
- [ ] 没有崩溃或异常到达用户
- [ ] 错误消息帮助用户纠正问题
- [ ] 所有无效输入以 WARNING 级别记录日志

#### FR-3.4：请求超时处理
**描述：** 强制执行最大请求处理时间。

**需求：**
- 每次请求最多 30 秒
- 超时适用于整个请求生命周期
- 超时时返回 HTTP 504
- 超时时取消正在进行的推理
- 记录超时事件

**验收标准：**
- [ ] 超过 30 秒的请求返回 HTTP 504
- [ ] 超时消息清晰
- [ ] 超时时清理资源
- [ ] 超时不影响其他请求

## 非功能需求

### NFR-1：性能

#### NFR-1.1：延迟需求
- **P50（中位数）：** CPU 上处理 224x224 图片 < 300ms
- **P95：** CPU 上处理 224x224 图片 < 500ms
- **P99：** CPU 上处理 224x224 图片 < 1000ms
- **健康检查：** < 100ms

**测量方式：** 延迟从收到请求到发送响应计算，不包括网络时间。

#### NFR-1.2：吞吐量
- 支持至少 10 个并发请求
- 推荐：在 t3.medium（AWS）或同等配置上支持 20-30 个并发请求
- 正常负载下 P95 延迟无劣化

#### NFR-1.3：资源使用
- **内存：** 正常负载下 < 2GB（单工作进程）
- **CPU：** 高效使用，无 CPU 密集型循环
- **启动时间：** 从容器启动到就绪 < 30 秒
- **关闭时间：** 在 10 秒内优雅关闭

#### NFR-1.4：可扩展性
- 应用必须是无状态的（无本地状态）
- 支持水平扩展（多个实例）
- 无文件系统依赖（模型权重除外）
- 线程安全或进程安全

## API 规范

### 请求头部

**必填：**
- `Content-Type: multipart/form-data`（用于 /predict）

**可选：**
- `X-Request-ID: <uuid>` - 客户端提供的关联 ID
- `Accept: application/json` - 响应格式（仅支持 JSON）

### 响应头部

**始终包含：**
- `Content-Type: application/json`
- `X-Correlation-ID: <uuid>` - 请求跟踪 ID
- `X-Response-Time: <ms>` - 以毫秒为单位的处理时间

**条件性：**
- `Retry-After: <seconds>` - 用于 503 和 429 响应
- `Cache-Control: no-cache` - 用于 /predict 端点

## 数据模型

### 预测对象
```python
from typing import TypedDict

class Prediction(TypedDict):
    class_name: str        # 人类可读的类别名称
    confidence: float      # 概率分数 (0.0 到 1.0)
    rank: int             # 在 top-K 中的排名（从 1 开始）
```

### 错误对象
```python
from typing import TypedDict, Optional

class Error(TypedDict):
    code: str                    # 错误码
    message: str                 # 人类可读的消息
    correlation_id: str          # 请求跟踪 ID
    timestamp: str              # ISO 8601 时间戳
    details: Optional[dict]      # 额外上下文（可选）
```

### 模型信息
```python
from typing import TypedDict, List

class ModelInfo(TypedDict):
    name: str                    # 模型名称
    framework: str               # ML 框架 (pytorch/tensorflow)
    version: str                 # 框架版本
    input_shape: List[int]       # 期望的输入形状 [H, W, C]
    output_classes: int          # 输出类别数量
```

## 错误处理

### HTTP 状态码

| 码值 | 含义 | 用途 |
|------|---------|-------|
| 200 | OK | 成功的预测或信息请求 |
| 400 | 错误请求 | 无效输入、格式错误的请求 |
| 413 | 负载过大 | 文件超出大小限制 |
| 415 | 不支持的媒体类型 | 错误的 Content-Type |
| 429 | 请求过多 | 超出速率限制 |
| 500 | 服务器内部错误 | 意外的应用错误 |
| 503 | 服务不可用 | 模型未加载、OOM、过载 |
| 504 | 网关超时 | 请求处理超时 |

### 错误码映射

```python
ERROR_CODES = {
    "INVALID_IMAGE_FORMAT": 400,
    "FILE_TOO_LARGE": 413,
    "MISSING_FILE": 400,
    "INVALID_PARAMETER": 400,
    "MODEL_ERROR": 500,
    "OUT_OF_MEMORY": 503,
    "TIMEOUT": 504,
    "RATE_LIMIT_EXCEEDED": 429,
    "INTERNAL_ERROR": 500,
}
```

## 安全需求

### 输入验证规则

```

X-Frame-Options: DENY
X-XSS-Protection: 1; mode=block
```

```bash
  -F "file=@dog.jpg" \
  -F "top_k=10" \
```

### Python 示例

```python
import requests

# 健康检查
response = requests.get('http://localhost:5000/health')
print(response.json())

# 进行预测
with open('dog.jpg', 'rb') as f:
    files = {'file': f}
    response = requests.post('http://localhost:5000/predict', files=files)
    print(response.json())
```
