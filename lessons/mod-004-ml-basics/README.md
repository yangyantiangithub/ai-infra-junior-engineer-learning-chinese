# Module 004: 面向基础设施工程师的机器学习基础

## 模块概述

欢迎来到机器学习基础模块！本模块弥合了传统基础设施工程与 AI/ML 系统专业领域之间的差距。你不会成为数据科学家——而是学习基础设施工程师需要了解的关于 ML 的知识，以便有效地构建、部署和维护 ML 系统。

## 为什么基础设施工程师需要 ML 知识？

作为 AI 基础设施工程师，你不是在训练前沿模型或调整超参数。但你需要：

- **部署**数据科学家训练的模型
- **构建**支持 ML 工作负载的基础设施
- **排查**模型在生产环境中的故障
- **优化**模型服务的性能
- **管理**模型生命周期和版本
- **监控**模型行为和资源使用情况

要有效做到这一点，你需要理解：
- ML 模型到底是什么（不仅仅是黑盒）
- 模型如何训练和保存
- 不同的模型格式及其影响
- 资源需求（CPU, GPU, 内存）
- 常见故障模式和调试策略

## 目标受众的现实情况

**你不是**：
- 需要从头实现 ML 算法
- 需要理解高级数学理论
- 负责模型架构设计
- 调整超参数或提高模型准确率

**你是**：
- 构建运行 ML 代码的基础设施
- 安全地将模型部署到生产环境
- 监控 ML 系统健康状态
- 与数据科学家协作
- 做出影响 ML 工作流的基础设施决策

## 学习目标

完成本模块后，你将能够：

### ML 基础
- 理解核心 ML 概念：训练、推理、特征、标签
- 区分监督学习、无监督学习和强化学习
- 识别常见 ML 任务：分类、回归、聚类
- 理解从数据到部署模型的 ML 工作流

### PyTorch 要点
- 加载和保存 PyTorch 模型
- 理解 tensor 和基本操作
- 使用预训练模型运行推理
- 识别 PyTorch 模型需求（依赖、硬件）
- 调试生产环境中的常见 PyTorch 问题

### TensorFlow 要点
- 加载和保存 TensorFlow/Keras 模型
- 理解 TensorFlow 模型格式（SavedModel, H5）
- 使用预训练 TensorFlow 模型运行推理
- 识别 TensorFlow 模型需求
- 从基础设施角度比较 TensorFlow 与 PyTorch

### 模型格式和互操作性
- 理解 ONNX（Open Neural Network Exchange）
- 在不同格式之间转换模型
- 识别何时需要进行格式转换
- 为部署场景选择合适的格式

### 基础设施注意事项
- 估算模型资源需求
- 理解 GPU 与 CPU 的权衡
- 认识模型大小和延迟约束
- 规划批量推理与实时推理
- 处理模型版本管理和回滚

## 实际背景

本模块中的所有内容都与基础设施工程直接相关：

### 模型部署
- **加载模型**：理解保存格式对部署至关重要
- **版本管理**：不同格式影响版本管理策略
- **回滚流程**：知道如何快速切换模型版本

### 资源管理
- **GPU 分配**：理解哪些操作需要 GPU
- **内存规划**：模型大小影响基础设施规模
- **批处理优化**：平衡延迟和吞吐量

### 故障排查
- **调试模型加载错误**：依赖版本不匹配
- **修复推理失败**：输入形状不匹配、设备错误
- **诊断性能问题**：识别 GPU 利用率不足

### 协作
- **与数据科学家沟通**：理解他们的需求
- **记录基础设施**：ML 特定的约束和能力
- **连接团队**：在 ML 和基础设施术语之间进行翻译

## 重要提示

### GPU 访问
虽然许多练习可以在 CPU 上运行，但拥有 GPU 访问权限能显著提升学习体验。如果你没有本地 GPU：

- 使用 Google Colab（免费 GPU 访问）
- 使用 AWS EC2 g4dn 实例（按小时付费）
- 使用 Paperspace Gradient（专注于 ML 的云服务）
- 专注于理解概念；在 CPU 上运行推理

### 下载要求
预训练模型可能很大（100MB 到数 GB）。确保你有：
- 稳定的互联网连接
- 足够的磁盘空间
- 对初始下载有耐心（之后会缓存）

### 框架安装
支持 CUDA 的 PyTorch 和 TensorFlow 需要特定版本的 CUDA。请仔细按照官方安装指南为你的系统进行安装。
