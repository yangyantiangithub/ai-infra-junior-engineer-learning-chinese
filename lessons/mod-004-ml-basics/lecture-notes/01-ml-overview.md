## 引言

### 基础设施工程师的视角

你不需要成为机器学习专家来构建 ML 基础设施。但你确实需要理解你正在部署的那些"黑盒"内部发生了什么。

可以这样理解：
- **Web 开发者**不需要理解 TCP/IP 包路由，但他们需要了解 HTTP 基础
- **数据库管理员**不需要编写查询优化器，但他们需要理解索引
- **ML 基础设施工程师**不需要设计神经网络，但他们需要理解训练与推理的区别

本讲座为你提供所需的 ML 知识——不多不少——让你在 AI 基础设施领域高效工作。

### 学习目标

到本讲座结束时，你将能够：
- 理解机器学习实际做了什么（揭开炒作的面纱）
- 识别 ML 工作流的各个阶段以及基础设施的定位
- 区分训练和推理（非常重要！）
- 识别不同类型的 ML 及其基础设施需求
- 根据 ML 任务类型预测资源需求
- 与数据科学家和 ML 工程师有效沟通

## 什么是机器学习？

### 传统编程范式

传统编程是显式的基于规则的逻辑：

```python
def classify_email(email_text: str) -> str:
    """传统基于规则的垃圾邮件检测"""
    spam_keywords = ["free money", "click here", "win now"]

    for keyword in spam_keywords:
        if keyword in email_text.lower():
            return "spam"

    return "not spam"
```

**这种方法的缺点：**
- 规则脆弱且容易被绕过
- 需要手动更新以应对新模式
- 无法处理细微差别或上下文
- 不会随着更多数据而改进

### 机器学习范式

机器学习从数据中学习模式：

```python
# ML 方法（概念性）
training_data = [
    ("free money win now!", "spam"),
    ("meeting tomorrow at 3pm", "not spam"),
    ("click here for prizes", "spam"),
    # ... 数千个更多示例
]

# 训练模型以学习模式
model = train_spam_classifier(training_data)

# 使用学到的模式对新的邮件进行分类
result = model.predict("limited time offer click now")
# 返回："spam"（学到的模式，而非硬编码规则）
```

**优势：**
- 学习人类难以明确表达的复杂模式
- 随着更多数据而改进
- 重新训练后适应新模式
- 处理细微差别和上下文

### 核心 ML 概念：函数逼近

从本质上讲，ML 是**函数逼近**：

**传统编程：**
```
规则（由程序员编写）+ 输入 → 输出
```

**机器学习：**
```
示例（数据）→ 学习函数 → 应用于新输入 → 输出
```

**具体示例 - 图像分类：**

```
传统：IF 像素匹配模式 X THEN 猫
ML：这里有一万张猫的图片和一万张狗的图片。
    找出它们的区别。
    现在告诉我这张新图片是猫还是狗。
```

### ML 擅长什么

✅ **模式识别** - 识别图像中的猫、检测欺诈
✅ **预测** - 股票价格、设备故障、客户流失
✅ **分类** - 垃圾邮件检测、情感分析、疾病诊断
✅ **生成** - 文本生成（GPT）、图像生成（DALL-E）
✅ **复杂决策** - 游戏（AlphaGo）、机器人技术

### ML 不擅长什么

❌ **精确计算** - 使用传统编程（2 + 2 = 4）
❌ **保证正确性** - ML 是概率性的，而非确定性的
❌ **解释决策** - 许多模型是"黑盒"
❌ **没有数据的任务** - ML 需要示例来学习
❌ **简单的基于规则的逻辑** - 当 `if/else` 足够时不要使用 ML

## ML 工作流

### 概述：从数据到部署模型

```
┌─────────────┐
│ 1. 数据     │  收集和准备训练数据
│ 收集        │
└──────┬──────┘
       │
┌──────▼──────┐
│ 2. 数据     │  清洗、转换、拆分数据
│ 准备        │
└──────┬──────┘
       │
┌──────▼──────┐
│ 3. 训练     │  从数据中学习模式
│             │  （这就是通常所说的"ML"）
└──────┬──────┘
       │
┌──────▼──────┐
│ 4. 评估     │  测试模型性能
│             │
└──────┬──────┘
       │
┌──────▼──────┐
│ 5. 部署     │  将模型部署到生产环境
│             │  （这是你的主要职责）
└──────┬──────┘
       │
┌──────▼──────┐
│ 6. 推理     │  对新数据进行预测
│             │  （这也是你的职责）
└──────┬──────┘
       │
┌──────▼──────┐
│ 7. 监控     │  跟踪性能、检测漂移
│             │  （这个也是）
└─────────────┘
```

### 阶段 1：数据收集

**发生什么：**
- 收集训练示例
- 标记数据（用于监督学习）
- 存储在数据库或数据湖中

**示例 - 情感分析：**
```
推文                            标签
"I love this product!"          positive
"Worst experience ever"         negative
"It's okay, nothing special"    neutral
```

**基础设施角色：**
- 为数据集提供存储
- 构建数据管道
- 确保训练数据可访问

### 阶段 2：数据准备

**发生什么：**
- 清洗数据（删除重复项、处理缺失值）
- 转换数据（归一化、编码分类变量）
- 拆分为训练/验证/测试集

**示例拆分：**
```
总数据集：10,000 个示例
├── 训练集：   7,000（70%）  ← 模型从中学习
├── 验证集： 2,000（20%）  ← 调整超参数
└── 测试集：   1,000（10%）  ← 最终评估
```

**基础设施角色：**
- 为数据处理提供计算资源
- 存储处理后的数据集
- 对数据集进行版本控制

### 阶段 3：训练（"学习"部分）

**发生什么：**
- 模型处理训练数据
- 调整内部参数以最小化错误
- 多次遍历数据（epochs）

**训练过程（简化）：**
```
for epoch in range(num_epochs):
    for batch in training_data:
        # 进行预测
        predictions = model(batch.inputs)

        # 计算误差（loss）
        loss = calculate_loss(predictions, batch.labels)

        # 更新模型以减小误差
        model.update_parameters(loss)
```

**可视化表示：**
```
Epoch 1: Loss = 0.8  ████████░░
Epoch 2: Loss = 0.6  ██████░░░░
Epoch 3: Loss = 0.4  ████░░░░░░
Epoch 4: Loss = 0.3  ███░░░░░░░
...
Epoch 20: Loss = 0.1  █░░░░░░░░░（模型训练完成！）
```

**基础设施角色（关键）：**
- 为训练提供 GPU/TPU 计算资源
- 管理训练作业调度
- 存储模型检查点
- 监控资源利用率
- 处理长时间运行的作业（数小时到数周！）

### 阶段 4：评估

**发生什么：**
- 在未见过的数据（测试集）上测试模型
- 计算指标（准确率、精确率、召回率等）
- 决定模型是否足够好用于生产

**示例指标：**
```
测试集结果：
├── 准确率（Accuracy）：92%
├── 精确率（Precision）：90%
├── 召回率（Recall）：88%
└── F1 分数：89%
```

**基础设施角色：**
- 为评估提供计算资源
- 存储评估结果
- 跟踪模型版本和指标

### 阶段 5：部署

**发生什么：**
- 打包训练好的模型
- 部署到服务基础设施
- 暴露 API 用于预测
- 实现监控和日志记录

**基础设施角色（你的主要工作）：**
- 构建模型服务基础设施
- 实现模型的 CI/CD
- 处理模型版本管理
- 实现 A/B 测试
- 确保高可用性和低延迟

### 阶段 6：推理（预测）

**发生什么：**
- 接收新输入
- 通过模型运行输入
- 返回预测

**示例 - 图像分类：**
```python
# 新图像到达
new_image = load_image("cat_photo.jpg")

# 通过已部署的模型运行
prediction = model.predict(new_image)
# 返回：{"class": "cat", "confidence": 0.95}
```

**基础设施角色：**
- 以低延迟提供预测
- 处理并发请求
- 批量处理请求以提高效率
- 监控预测质量

### 阶段 7：监控和重新训练

**发生什么：**
- 监控模型在生产环境中的性能
- 检测数据漂移（输入分布变化）
- 检测概念漂移（关系变化）
- 在需要时触发重新训练

**示例漂移检测：**
```
第 1 周：平均预测置信度：0.92 ✓
第 2 周：平均预测置信度：0.90 ✓
第 3 周：平均预测置信度：0.85 ⚠️
第 4 周：平均预测置信度：0.75 ❌（重新训练！）
```

**基础设施角色：**
- 实现监控仪表板
- 记录预测和特征
- 自动化重新训练管道
- 管理模型版本

## 机器学习类型

### 监督学习

**定义：** 从带标签的示例中学习（输入 + 正确输出）

**类比：** 跟着提供答案的老师学习

**示例：**
```
训练数据：
猫的图片   → 标签："cat"
狗的图片   → 标签："dog"

训练后：
新图片      → 预测："cat"（无需标签！）
```

**常见任务：**
- 分类（输出是类别）
- 回归（输出是数字）

**基础设施注意事项：**
- 需要带标签的训练数据（创建成本可能很高）
- 训练可能需要大量计算
- 推理通常很快

### 无监督学习

**定义：** 在没有标签的情况下从数据中发现模式

**类比：** 自己探索学习

**示例 - 聚类：**
```
训练数据：
客户 1：年龄=25，收入=$50k，购买次数=10
客户 2：年龄=24，收入=$48k，购买次数=12
客户 3：年龄=55，收入=$90k，购买次数=5
客户 4：年龄=58，收入=$95k，购买次数=4

算法对相似客户进行分组：
聚类 1：年轻、中等收入、频繁购买者
聚类 2：年长、高收入、不频繁购买者
```

**常见任务：**
- 聚类（将相似的示例分组）
- 降维（压缩数据）
- 异常检测（发现异常值）

**基础设施注意事项：**
- 不需要标签（数据更便宜）
- 可以处理大量数据
- 训练可能需要更多计算资源

### 强化学习

**定义：** 通过试错和奖励进行学习

**类比：** 用零食训练狗

**示例 - 游戏：**
```
动作：移动棋子 → 结果：输掉游戏 → 奖励：-1
动作：不同的走法 → 结果：赢得游戏 → 奖励：+1

多次游戏后：学会下棋！
```

**常见任务：**
- 游戏（国际象棋、围棋、电子游戏）
- 机器人技术（学习走路、抓取物体）
- 资源优化（数据中心冷却）

**基础设施注意事项：**
- 需要模拟环境（成本高昂）
- 训练极其消耗计算资源
- 训练可能需要数天到数月
- 推理通常很快

### 半监督和自监督学习

**半监督学习：** 混合使用带标签和未标签的数据

**自监督学习：** 从数据本身创建标签

**示例 - 自监督：**
```
原始句子："The cat sat on the mat"

训练示例：
输入：  "The cat ___ on the mat"
输出： "sat"

模型学习语言模式，无需手动标记！
```

**基础设施注意事项：**
- 降低标记成本
- 可以利用大量未标记的数据集
- 被 BERT、GPT 等模型使用

## 常见 ML 任务

### 分类

**做什么：** 将输入分配到几个类别之一

**示例：**
- 邮件：垃圾邮件或非垃圾邮件
- 图像：猫、狗、鸟等
- 医疗：疾病诊断
- 情感：正面、负面、中性

**输出：** 类别标签

**基础设施需求：**
- **训练：** 中等至高计算量（复杂任务需要 GPU）
- **推理：** 快速（毫秒级）
- **模型大小：** 不等（MB 到数 GB）

### 回归

**做什么：** 预测连续的数值

**示例：**
- 房价预测
- 温度预测
- 股票价格预测
- 设备故障时间估计

**输出：** 数字（如 $325,000、72.5°F、14.3 天）

**基础设施需求：**
- **训练：** 中等计算量
- **推理：** 非常快（微秒到毫秒级）
- **模型大小：** 通常较小（MB）

### 目标检测

**做什么：** 识别并定位图像中的物体

**示例：**
```
输入：街景图像
输出：[
  {object: "car", bbox: [100, 200, 300, 400], confidence: 0.95},
  {object: "person", bbox: [350, 180, 450, 350], confidence: 0.92},
  {object: "sign", bbox: [500, 100, 600, 200], confidence: 0.88}
]
```

**基础设施需求：**
- **训练：** 高计算量（需要 GPU）
- **推理：** 中等速度（实时需要 GPU）
- **模型大小：** 大（数百 MB 到 GB）

### 自然语言处理（NLP）

**做什么：** 理解和生成人类语言

**示例：**
- 文本分类（情感分析）
- 命名实体识别（提取名称、日期、地点）
- 机器翻译
- 文本生成（ChatGPT 等）

**基础设施需求：**
- **训练：** 非常高的计算量（大模型需要多个 GPU）
- **推理：** 不等（简单的 NLP 很快，大语言模型较慢）
- **模型大小：** 差异很大（MB 到数百 GB）

### 推荐系统

**做什么：** 推荐用户可能喜欢的项目

**示例：**
- Netflix 电影推荐
- Amazon 产品推荐
- Spotify 音乐播放列表
- YouTube 视频推荐

**基础设施需求：**
- **训练：** 高计算量和内存（大数据集）
- **推理：** 快速（必须扩展到数百万用户）
- **模型大小：** 可能非常大（GB 到 TB 的 embeddings）

## 基础设施影响

### 训练 vs 推理：关键区分

**训练（偶尔发生）：**
- 处理整个数据集（数百万个示例）
- 运行数小时、数天或数周
- 需要大量计算资源（GPU/TPU）
- 高内存需求
- 可以容忍延迟
- 以批处理模式进行

**推理（持续发生）：**
- 处理单个输入（或小批量）
- 需要在毫秒内返回结果
- 有时可以使用 CPU
- 较低的内存需求
- 延迟是关键
- 实时进行

**基础设施影响：**
```
训练：
├── 基础设施：高端 GPU 集群
├── 调度：批处理作业系统
├── 成本模型：按预留容量付费
└── 优化：优先吞吐量而非延迟

推理：
├── 基础设施：优化的服务层
├── 调度：实时请求处理
├── 成本模型：按预测付费
└── 优化：优先延迟而非吞吐量
```

### 按模型类型的资源需求

#### 小模型（< 100MB）
```
示例：简单分类器、回归模型
训练：
- CPU 通常足够
- 训练数小时
- GB 级 RAM

推理：
- CPU 即可
- 亚毫秒级延迟
- 每台服务器可处理数千 QPS
```

#### 中等模型（100MB - 5GB）
```
示例：ResNet, BERT base
训练：
- 推荐 GPU
- 数小时到数天
- 10-100GB RAM

推理：
- 实时需要 GPU，批处理可用 CPU
- 10-100ms 延迟
- 每个 GPU 数百 QPS
```

#### 大模型（5GB - 100GB）
```
示例：大型视觉模型、BERT large
训练：
- 需要多个 GPU
- 数天到数周
- 100-500GB RAM

推理：
- 需要 GPU
- 100-1000ms 延迟
- 每个 GPU 数十 QPS
```

#### 超大模型（> 100GB）
```
示例：GPT-3, GPT-4, 大型多模态模型
训练：
- 分布在数百到数千个 GPU 上
- 数周到数月
- TB 级 RAM

推理：
- 每个预测需要多个 GPU
- 1-10+ 秒延迟
- 每个实例个位数 QPS
```

### 成本考虑

**训练成本：**
- GPU 小时：$1-$30+ 每小时，取决于 GPU 类型
- 存储：$0.02-$0.10 每 GB/月
- 数据处理：CPU 计算和 I/O 成本

**推理成本：**
- 每请求：$0.0001 - $0.01+ 每个预测
- GPU 利用率：保持 GPU 忙碌以分摊成本
- 自动扩展：平衡成本和延迟 SLA

**示例成本计算：**
```
模型：BERT-base 用于情感分析
训练（一次性）：
- 8 x A100 GPU × 24 小时 × $2.50/hr = $480

推理（每月）：
- 每天 1000 万次预测
- 每次预测 100ms
- 2 个 GPU 实例 24/7 运行
- 2 × 720 小时 × $1.50/hr = $2,160/月
```

## 总结

### 关键要点

1. **ML 从数据中学习模式**，而非显式编程
2. **训练和推理有本质区别**——理解这一区别！
3. **不同的 ML 类型**（监督、无监督、RL）有不同的基础设施需求
4. **常见任务**（分类、回归、NLP）有可预测的资源需求
5. **ML 系统很复杂**——远不止"模型"一个组件
6. **基础设施至关重要**——没有好的基础设施，模型毫无用处

### 基础设施工程师的心智模型

当你遇到 ML 项目时，问自己：

✅ **模型需要多久重新训练一次？**
✅ **预期的查询量是多少？**
✅ **使用了什么框架？（PyTorch, TensorFlow 等）**
